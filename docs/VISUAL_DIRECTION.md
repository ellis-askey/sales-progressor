# Visual Direction

> **Scope (2026-11-02): un-migrated production pages only.** This records the earlier
> agent-app aesthetic (warm, glassmorphism). It is **not** the authority for new UI.
> New UI and founder-approved redesigns follow the forward **TSP Liquid Glass** system —
> [`docs/reference/design-system/`](reference/design-system/README.md) (materials, tokens,
> components). Where this doc and the design system disagree for new work, the design
> system wins. Retained for historical/production reference; intentionally not rewritten.

## Purpose

This product must not feel like a generic SaaS dashboard.

It should feel premium, calm, polished, and modern, with a strong sense of visual refinement across the entire app.

The aesthetic direction is inspired by high-end Apple-like UI, glassmorphism, and beautifully layered digital products, but it must remain practical, readable, and suitable for a real business platform.

This is a UK property sales progression platform, not a design concept piece. The design should feel trustworthy, elegant, and product-grade.

---

## Core Visual Goal

The app should feel:

- premium
- calm
- modern
- elegant
- polished
- soft
- layered
- high-end
- intentionally designed

The app should not feel:

- generic
- template-like
- flat
- clunky
- harsh
- crowded
- overly corporate
- visually noisy
- cheap SaaS

---

## Overall Design Language

### General Feel
The UI should feel like a refined premium application with:

- soft glass-like surfaces
- subtle translucency where appropriate
- layered depth
- rounded cards and panels
- carefully controlled shadows
- elegant spacing
- more considered hierarchy
- polished controls and navigation

The goal is not flashy design. The goal is quiet quality.

---

## Materials and Surfaces

### Cards and Panels
Cards should feel elevated and refined.

Use:
- soft rounded corners
- subtle border definition
- gentle translucency where appropriate
- layered surfaces
- light blur where useful
- restrained shadow depth

Avoid:
- flat boxes with no depth
- hard borders everywhere
- muddy low-contrast glass
- excessive blur
- over-styled “dribbble” concepts

### Glassmorphism
Glass effects should be used tastefully, not everywhere.

Use glass-style surfaces mainly for:
- navigation shells
- floating panels
- summary cards
- modals
- overlays
- premium dashboard sections

Do not overuse glass on every element.

Glass should feel:
- subtle
- clean
- light
- premium
- readable

Never let the glass treatment reduce usability.

---

## Depth and Layering

The app should feel dimensional rather than flat.

Use:
- clear separation between background, shell, and content
- multiple surface levels
- subtle elevation changes
- refined shadows and highlights
- careful use of translucency

Avoid:
- everything sitting on the same flat plane
- heavy dark shadows
- extreme glows
- cluttered layering

Depth should create calm hierarchy, not visual drama.

---

## Colour Direction

The colour palette should feel calm and premium.

Use:
- soft neutral bases
- cool refined tones
- carefully chosen accent colours
- restrained highlights
- subtle status colours

Avoid:
- oversaturated gradients everywhere
- harsh SaaS blues as the whole identity
- too many competing accent colours
- loud enterprise colour palettes

Status colours should feel polished:
- success = calm and clean
- warning = noticeable but not aggressive
- error = clear but not visually harsh
- inactive/locked = soft, muted, intentional

---

## Typography

Typography should feel more elegant and premium than default dashboard UI.

Use:
- strong hierarchy
- larger, cleaner headings
- restrained supporting text
- comfortable line spacing
- concise body copy

The typography should feel:
- modern
- calm
- legible
- high quality

Avoid:
- cramped text
- tiny labels everywhere
- too many font weights
- text-heavy interfaces
- default “admin panel” hierarchy

---

## Spacing and Layout Rhythm

Spacing is a major part of the premium feel.

Use:
- generous spacing between sections
- strong internal card padding
- clear grouping
- breathing room around key actions
- balanced layouts

Avoid:
- cramped dashboards
- too many cards jammed together
- inconsistent padding
- uneven vertical rhythm

If in doubt, add clarity and breathing room.

---

## Controls and Inputs

### Buttons
Buttons should feel polished and intentional.

Use:
- rounded shapes
- clear primary vs secondary hierarchy
- subtle depth
- refined hover/focus/active states
- premium, tactile feel

Avoid:
- default flat button styling
- inconsistent button sizes
- aggressive gradients
- overly bright CTA styling

### Inputs
Inputs should feel clean, high-quality, and modern.

Use:
- refined field surfaces
- clear labels
- elegant focus states
- strong spacing

Avoid:
- plain default form styling
- cramped labels
- raw browser-feeling inputs

### Tabs / Segmented Controls / Filters
These should feel especially polished.

Use:
- subtle pill or segmented control treatment
- clear active state
- good contrast
- elegant spacing

They should feel more product-grade and less “framework default”.

---

## Navigation and App Shell

Navigation should feel like part of a premium application shell.

Use:
- refined sidebars
- clean top bars
- layered shells
- controlled translucency where appropriate
- a sense that the app lives inside a designed environment

Avoid:
- plain template sidebars
- boxy nav sections
- unstyled utility navigation
- visual mismatch between pages

The shell should unify the whole product.

---

## Dashboard Feel

Dashboards should feel premium, not generic.

Use:
- better hierarchy
- larger, calmer summary cards
- refined surface treatment
- strong spacing between major sections
- elegant filtering and action zones
- more visual intent

Avoid:
- tiled generic SaaS admin blocks
- too many identical cards
- default analytics styling
- overloading users with clutter

Each dashboard should feel useful, calm, and polished.

---

## Tables, Lists, and Data Views

Even dense data views should feel refined.

Use:
- clear row spacing
- elegant dividers
- polished hover states
- readable hierarchy
- subtle surface treatment

Avoid:
- flat spreadsheet-like harshness
- overly dense tables
- weak alignment
- cramped row heights

The app can be information-rich without feeling ugly.

---

## Modals, Drawers, and Overlays

Overlays should feel premium and focused.

Use:
- soft elevated surfaces
- clean backgrounds
- elegant spacing
- restrained backdrop blur
- strong close/cancel behaviour

Avoid:
- plain default modals
- overly dark overlays
- cluttered modal content
- inconsistent modal styling

---

## Empty States and Secondary Screens

Even secondary pages should feel intentional.

Use:
- soft illustration or icon support where appropriate
- good spacing
- helpful copy
- premium card styling

Avoid:
- blank, harsh empty areas
- obvious placeholder feeling
- weak layout structure

No part of the app should feel neglected.

---

## Role-Based Experiences

This product has multiple user types:
- internal admin / progression team
- estate agents
- buyer / seller portal users

The visual system must feel consistent across all three, but the experience should still feel correctly tailored.

### Admin / Internal
Should feel powerful, professional, information-rich, and controlled.

### Agent
Should feel capable, premium, and highly usable, with the same polish as admin but slightly more focused and commercially practical.

### Buyer / Seller Portal
Should feel calm, reassuring, simple, and beautifully guided, with less density and more emotional clarity.

Do not make all roles look identical.
Do keep them within the same design language.

---

## Product Fit

This is a serious operational product.

Style must never reduce:
- readability
- usability
- trust
- responsiveness
- accessibility
- task completion clarity

The app must remain easy to use during stressful real-world property transactions.

Beauty should support trust and clarity, not distract from them.

---

## What to Avoid

Do not drift into:

- generic SaaS dashboard visuals
- flat Tailwind starter-kit styling
- overdone neon gradients
- dark cyberpunk fintech style
- gimmicky glass everywhere
- blurry unreadable text
- overly low contrast UI
- visual clutter
- style over function
- inconsistent component styling

---

## Component Consistency Rules

Shared components should be visually unified.

Prioritise consistency across:
- cards
- buttons
- inputs
- tabs
- badges
- sidebars
- headers
- empty states
- modals
- page shells

If introducing a new visual pattern, first check whether an existing pattern should be upgraded and reused instead.

---

## Implementation Rules

When upgrading visuals:

- prefer reusable design tokens
- use shared component patterns
- avoid one-off visual hacks
- preserve responsiveness
- preserve accessibility
- preserve business logic
- preserve role separation
- preserve clarity of workflows

The visual system should scale cleanly as the app grows.

---

## Final Standard

Every page should feel like part of a high-quality modern product.

The app should feel:

- beautifully designed
- clearly structured
- premium without arrogance
- soft without being vague
- modern without being gimmicky
- polished without losing practicality

If unsure, choose the more elegant, calmer, cleaner option.
