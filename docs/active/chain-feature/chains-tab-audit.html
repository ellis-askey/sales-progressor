What the Chains tab can honestly do

The tab's only had one pass, and “Oldest sale” exposed the real constraint: we can only build on what agents genuinely share with each other. So this starts there — the honest data palette — then audits what's on the tab today and lays out everything we could build on top of it. Nothing here invents a number we don't have.

02 The tab today

Five tabs (In chains · Check-ins · Push to exchange · Needs chain setup · No chain) — all sound, keep them. The weak spots are in the summary metrics, which have never been pressure-tested against the palette above.

Summary metricWhat it really doesVerdict
Chain value Sum of priced nodes. Real prices, honest. Keep
Claim rate Claimed links ÷ total. A real connection measure. Keep
Oldest sale “N days” Time since the file was claimed into the chain — not since the sale was agreed. Misreads a months-old sale linked yesterday as brand new. Drop
Weakest link Heuristic: withdrawn → dead invite → lowest-progress file only if ≥20 pts behind. Right idea, blunt rule. Rebuild
Chain risk High / Med / Low Heuristic partly built on the same proxies (incl. the 90-day “oldest file” rule). Rebuild
Predicted completion Hard-gated off (MEDIANS_READY = false) — the row has never once rendered. Dead · decide

The four workspace tiles (Active sales · In chains · Need setup · Agents to invite) are all honest counts — keep. The gap is that the richest signal we have — live progress — is barely used: one pooled % per node, no movement, no spread, no bottleneck.

BMomentum — the one thing missing, and the biggest win

We never store yesterday's %, so we can't see movement. Snapshot the shared % daily (tiny, cheap) and a whole honest layer opens up — this is what “Oldest sale” was fumbling toward.

04 What we deliberately won't build

So we never ship a number we can't stand behind. These need data that stays private to the other side.

✕
Their predicted exchange date — private forecast, stripped at the wire. We can show readiness, not a date.
✕
Which milestone / step they're stuck on — we get a %, never the step behind it.
✕
Their enquiries, documents, individual price — never selected into the chain read.
✕
“Oldest sale since agreed” — no reliable offer-accepted date exists across files; even createdAt is only a proxy. This is why #236 was right.

05 A recommended first pass

Ordered by honesty-per-effort. The first three are the heart of the fix.

Drop “Oldest sale,” rebuild the summary on live progress

Remove the misleading row; lead instead with chain progress + bottleneck node, both facts.

Effort: small · no new data

Add a daily progress snapshot → momentum

One tiny table storing each claimed node's % over time. Unlocks stall detection, “moved this week,” and slowest-moving — the honest answer to what “oldest sale” was reaching for.

Effort: medium · one small new store

Rebuild “Weakest link” and “Chain risk” on real signals

Weakest link = slowest / most-stalled node. Risk = withdrawals + dead invites + stall + unclaimed, no proxy ages.

Effort: small–medium

Progress spread on the chain card + chase-the-bottleneck

Mini per-node bars at a glance, and one tap from “slowest” to the existing chase flow.

Effort: small

Decide “Predicted completion”: wire the medians or remove the dead row

It's been invisible since launch. Either turn it on honestly or delete it.

Effort: your call

Clear or date-stamp “ready to exchange” so it can't go stale on the other agent's view.
