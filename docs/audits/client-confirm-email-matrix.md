# Client confirm-step email matrix

Every client-facing milestone email (Seller / Buyer), rendered from the real send-path code across the transaction-type matrix, for a voice audit.

## What this is

Generated by a throwaway script that resolves each email exactly as `lib/services/portal.ts` does: the base copy from `getMilestoneCopy(code).emailCopy`, layered with the Sales Progressor default overrides (`getOverridesForCode(code, null)`), for the scenario `{ tenure, method }` where method is normalised (`mortgage` vs `cash`). Only the `vendor` (Seller) and `purchaser` (Buyer) recipients are shown — internal progressor / agent copies are omitted.

## The six permutations

Purchase method x tenure:

- Mortgage + Freehold
- Mortgage + Leasehold
- Cash buyer + Freehold
- Cash buyer + Leasehold
- Cash (from sale proceeds) + Freehold
- Cash (from sale proceeds) + Leasehold

## How to read the variants

- Where the rendered text is identical across every permutation that receives the email, it is shown once as **All transaction types**.
- Where it differs, each distinct variant lists the permutations that produce it.
- Some milestones do not apply to some permutations (no email sent): management-pack steps (VM8, VM9, PM12) are freehold-not-applicable (leasehold-only); mortgage steps (PM5, PM6, PM11) are cash-not-applicable (mortgage-only); the deposit step (PM24) is not applicable to cash-from-proceeds. These are excluded from that email's variants and called out per milestone.

## Dynamic-content placeholders

Runtime values are shown as guillemet placeholders so the auditor sees where live content lands: `«property address»`, `«event date»`, `«valuation date»`, `«surveyor firm»`, `«completion date»`.
PM6 (lender valuation) notes are rendered for the physical-visit branch. When no visit date is captured the live email swaps to a desktop-valuation phrasing ("a desktop valuation (no physical visit required)" / "No physical visit to the property is needed. The assessment is conducted remotely."). That swap is runtime-driven, not method/tenure-driven.
