# How Milestones Work

Milestones are the structured checklist of legal and procedural steps that make up a residential sale. Sales Progressor tracks 20 vendor milestones (VM1–VM20) for the seller's side and 27 purchaser milestones (PM1–PM27) for the buyer's side.

## Why milestones matter

A sales progression file without milestones is just a list of contacts. Milestones turn a file into a managed process — they show exactly where each side stands, drive the reminder and chase system, feed the progress percentage, and gate exchange.

## The four states

Every milestone is in exactly one of four states:

| State | Description |
|---|---|
| **Locked** | A required predecessor milestone has not been completed yet. This milestone cannot be acted on. |
| **Available** | Ready for action. Once Available, the reminder clock starts. |
| **Complete** | Marked as done. The date of completion is recorded. |
| **Not Required** | Does not apply to this transaction. Excluded from progress calculations. |

## Predecessor rules (why milestones get unlocked)

Most milestones have a predecessor — another milestone that must be complete before this one becomes Available. For example:

- VM3 (seller's welcome pack received) is locked until VM1 (seller instructed solicitor) is complete.
- PM7 (draft contract pack received by buyer's solicitor) is locked until VM7 (draft contract pack issued) is complete — because the buyer cannot receive what has not been issued.

Some milestones have no predecessor and start Available immediately when the file is created. VM1 and PM1 (both "instructed solicitor") are examples — they can be marked complete as soon as a new file is opened.

Cross-side predecessors exist too: some purchaser milestones depend on vendor milestones having been completed first. This reflects the real legal interdependency between the two sides of a sale.

## Cascade when completing

When a milestone is marked Complete, the system automatically:

1. Checks whether any Locked milestones use this as their predecessor
2. Unlocks (sets to Available) any that do
3. Starts their reminder clocks

This cascade happens immediately on save — there is no manual step to unlock the next milestone.

## Cascade when marking Not Required

If a milestone is set to Not Required:

1. Any milestones that were locked waiting for it are also set to Not Required, because they are waiting on something that will never happen.
2. The Not Required cascade continues through as many levels as needed.

## Cascade when unmarking a completion

If you revert a milestone from Complete back to Available:

1. All downstream milestones that depended on it revert to Locked.
2. Their completion dates are cleared.

This prevents a file showing false progress after a correction.

## Progress percentage

The progress percentage shown in the file header is calculated as:

```
progress = sum(complete milestone weights) / sum(all applicable milestone weights)
```

"Applicable" means everything except Not Required milestones. Each milestone has a weight reflecting its significance in the overall process. Exchange-related milestones (VM18, PM25) have high weights; administrative early-stage milestones have lower weights.

## The reminder clock

Once a milestone becomes Available, the reminder system starts tracking it. After a grace period (different for each milestone), if the milestone has not been completed, a reminder becomes active in the Reminders page and Reminders tab. See [How the reminder system works](../04-reminders-and-chasing/how-reminders-work).
