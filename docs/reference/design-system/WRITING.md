# Liquid Glass — writing & terminology

Extends the house voice in [`../VOICE.md`](../VOICE.md) (still authoritative for the
locked phrases and the voice gate, Law 21). This adds the **interface-copy rules**
for the Liquid Glass era. Nothing here changes legal, financial or transaction
terminology — see "Don't touch" below.

## Rules

- **Natural British English.** Colour, organise, apologise, -ise.
- **Sentence case** everywhere — labels, headings, buttons, dates, filters, status.
- **No uppercase for hierarchy.** Use weight/size/colour instead. (Acronyms like
  ID, EPC, TA6, HMRC stay as-is.)
- **Short, meaningful labels.** "New note", not "Create a new note entry".
- **Cut redundant explanation.** If the interface is self-explanatory, drop the
  subtitle. One subtitle per screen at most, and only if it adds information.
- **No marketing language, no filler instructions.** ("Everything you need, all in
  one place" → delete.)
- **Familiar property-industry terms.** Buyer/seller (not purchaser/vendor in
  client-facing copy), exchange, completion, enquiries, searches, chain, solicitor.
- **Friendly, clear, professional.** Calm even when the news is bad.
- **Consistent terminology across pages** (table below).
- **No technical language** in user-facing copy (no status enums, milestone codes,
  "the system", "automatically" — use "we'll"). (VOICE.md Law 21 list still applies.)

## Good vs poor

| Poor | Good | Why |
|---|---|---|
| `UPDATES` | `Updates` | Sentence case; hierarchy from type |
| `What's happened across your files.` (on every page) | *(omit when obvious)* | Redundant subtitle |
| `Create New Note Entry` | `New note` | Short, meaningful |
| `PROPERTY STATUS: ACTIVE` | `● Active` | Quiet status, no shouting |
| `The system automatically notified the buyer` | `We let the buyer know` | No self-reference/tech |
| `Click here to proceed to the next step` | `Next` | No filler |
| `Vendor` / `Purchaser` (to a client) | `Seller` / `Buyer` | Familiar terms |

## Terminology map (use consistently)

| Concept | Use | Avoid |
|---|---|---|
| The transaction | sale / file | round, deal, case (internal only) |
| The person buying | buyer (client-facing) / purchaser (internal/legal) | — |
| The person selling | seller (client-facing) / vendor (internal/legal) | — |
| Delete/remove | remove | delete |
| Progress steps | milestones / steps | stages codes (VM/PM…) in UI |
| The client view | portal | — |

## Don't touch

Do not change the meaning of legal, financial or transaction terminology
(exchange, completion, deposit, memorandum of sale, TA6/TA10, enquiries,
requisitions on title, etc.). Do not rename an established business concept
without checking its use across the app first. Do not remove genuinely useful
information in the name of brevity.
